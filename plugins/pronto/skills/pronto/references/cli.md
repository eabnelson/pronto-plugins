# Pronto on a Mac

## What the `pronto` command is for

Pronto for Mac (`https://pronto.ooo/download`) turns on iMessage and WhatsApp and runs the Channel Host that answers them. Its helper, the `pronto` command, is for this device only: signing in, checking the Channel Host and each channel, repairing it, and recovering requests it could not finish. Do all workspace work (reading, saving, posting, sharing, Apps, administration, approvals, external connections) through the connected Pronto tools, not the command. Workspace commands such as `context create`, `actions invoke`, `artifacts download` and `connections` don't exist and answer `unknown_command`. An always-on Agent uses its own Agent credential from a setup link, not this command. Never ask the user to paste an access token, refresh token, authorization code, or credential into the conversation.

## Start once per device task

1. The command ships inside the app at `/Applications/Pronto.app/Contents/Helpers/pronto`, and Sparkle updates it with the app. There is nothing to install or update separately. Use that absolute path as `<pronto-path>` for every command in this task, including over SSH. Don't rely on `pronto` from `PATH`: another product, public Pronto, installs a command with the same name. If the app is missing, send the user to `https://pronto.ooo/download`.
2. Run `<pronto-path> status --json`. It reads only local state and reports `signIn`, the Channel Host (`host.state`, `host.daemon`) and each channel. Add `--check` for the full diagnosis, which calls the service and can take tens of seconds.
3. If `signIn` is `signed_out` or a command reports `not_signed_in`, run `<pronto-path> auth start --json`. Relay its non-secret `verificationUriComplete` and short `userCode` at once, tell the user they may open it on any device, then run `<pronto-path> auth poll --wait --json`, which returns when the sign-in is approved, declined or expired. Never ask for the resulting token, never paste a credential into chat, and never repeat sign-in in a loop.

Every command prints one JSON object (setup prints one event per line). `<pronto-path> help --json` lists every command; don't copy its schemas into this skill.

## Messaging channels on a Mac

- To turn on iMessage or WhatsApp, send the user to Pronto for Mac. It signs in, guides the macOS permissions for iMessage, links WhatsApp with a QR or pairing code, and sets each channel's tag and Agents. WhatsApp direct chats and groups both work. Web and iOS Connections edit each channel's tag and Agents too. Treat messaging channels as a separate setup surface from external provider connections: a channel is where people message the Studio (the app itself, iMessage, WhatsApp); a connection is an account its agents use (GitHub).
- A channel's tag and Agents can also be changed through the connected Pronto tools with `channel.settings.update` (`payload.scope: "agent_route"` for its ordered Agents; `"studio_binding"` with `handle` for its tag, which keeps the channel's own `guestGroupPolicy` when none is given), or on the Mac with `<pronto-path> channels routes get` and `channels routes set`. Show the user the channel, Studio, and tag first; the old tag stops working in existing chats.
- To stop one Mac, retire that device's connection with `channel.settings.update` through the Pronto tools (`status: "retired"`). Never use `connection.disconnect` for messaging channels; it is provider-wide and is refused with `channel_provider_device_scoped`.
- The Channel Host's own credential is derived from the Mac's Pronto sign-in; never expect, request, or relay a second device code, and never copy credentials between the two. It keeps working after `auth logout`. If a `channels host` command reports `authentication_failed`, follow its remediation; on a signed-in Mac that is `<pronto-path> channels host login`, which re-derives the host credential from the same sign-in without a new code. Stale host credentials are replaced automatically; only `channel_host_credential_stale` needs the owner to delete `studio-four-channel-host` items in Keychain Access.
- macOS grants Full Disk Access and Automation to Pronto.app, which runs the Channel Host as its own LaunchAgent, `ooo.pronto.app.host`. In groups, the verified sender is the actor and every participant is the disclosure audience, so an unresolved participant must fail closed before Studio discovery or agent execution.
- `<pronto-path> channels doctor` diagnoses the Channel Host without changing it, and `<pronto-path> channels repair` applies the safe local repairs it reports. Requests the host could not finish are listed by `<pronto-path> channels requests list`. `channels requests retry --event <id>` queues one retry of a proven pre-execution failure, and `channels requests manual-completed --event <id> --receipt <provider-id>` records one already answered by hand.

## Failure behavior

Use the error's `code`, `retryable` and `remediation` fields. Retry a retryable request once. Stop on credential-store, authorization, or repeated service failures and report the safe remediation without printing raw headers, OAuth responses, or credentials. If a command asks for an update, tell the user to choose Check for Updates… in Pronto's menu; never download a command yourself.
